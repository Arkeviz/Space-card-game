# Звёздные империи (веб)

Браузерная версия колодостроительной карточной игры «Звёздные империи» (по мотивам Star Realms): дуэль 1 на 1 по сети. Сервер авторитетный: правила считает он, клиент только отправляет намерения и показывает результат.

## Возможности

- Игра 1 на 1: создание матча с кодом, вход по коду или быстрая игра (сервер сам подбирает соперника).
- Имена игроков, реванш после партии, причина конца партии (авторитет, сдача, отключение, бездействие).
- Анимации карт, перетаскивание мышью, полное управление с клавиатуры, горячие клавиши (P, A, E).
- Настройки (скорость и режим анимаций, предупреждение перед концом хода и др.) и справка по правилам (клавиша `?`).
- Каталог всех карт с фильтрами и сортировкой (`/cards`).
- Партии хранятся в PostgreSQL 14 дней: после перезапуска сервера идущие партии продолжаются.

## Стек

Монорепозиторий на pnpm:

| Пакет | Что внутри |
| --- | --- |
| `packages/engine` | правила игры: чистый TypeScript без ввода-вывода |
| `packages/protocol` | схемы сообщений клиент/сервер (Zod) |
| `apps/server` | Fastify, WebSocket, PostgreSQL через Drizzle |
| `apps/client` | Vue 3, Vite, Pinia, GSAP, структура по [FEOD](https://feod.zede169778.workers.dev/) |

## Быстрый старт

Нужны Node.js 24+ и pnpm 11. Docker нужен только для базы данных и для запуска всего стека в контейнерах.

```bash
pnpm install
pnpm dev:server    # сервер, порт 3001
pnpm dev:client    # клиент, http://localhost:5173
```

Откройте игру в двух вкладках (лучше в разных профилях браузера: имя и настройки хранятся в `localStorage`) и нажмите «Быстрая игра» в обеих.

Без базы данных сервер работает, но партии живут только в памяти. Чтобы они сохранялись:

```bash
pnpm db:up                                              # PostgreSQL в Docker
cp apps/server/.env.example apps/server/.env            # DATABASE_URL для сервера
```

### Весь стек в Docker

```bash
pnpm docker:up     # PostgreSQL + сервер + клиент, http://localhost:8080
```

### GitHub Pages (необязательно)

Workflow `.github/workflows/pages.yml` публикует клиент на GitHub Pages. Pages раздаёт только статику, поэтому игровой сервер нужно держать отдельно (с `wss://`), а его адрес задать переменной репозитория `PAGES_WS_URL` (например, `wss://game.example.com/ws`). Без сервера на опубликованном сайте работают лобби без игры, каталог карт и справка.

- Включить: Settings -> Pages -> Source: GitHub Actions.
- Ручной деплой: Actions -> Deploy to GitHub Pages -> Run workflow.
- Автоматический деплой при каждом пуше в `main`: переменная репозитория `DEPLOY_PAGES` = `true` (Settings -> Secrets and variables -> Actions -> Variables). Пока флага нет, пуш деплой не запускает.

## Проверки

```bash
pnpm lint          # ESLint (antfu)
pnpm typecheck
pnpm test
```

Интеграционный тест хранилища идёт против настоящего PostgreSQL, если задан `TEST_DATABASE_URL` (подробности в [apps/server/README.md](apps/server/README.md)). CI (GitHub Actions) прогоняет то же самое и собирает Docker-образы.
