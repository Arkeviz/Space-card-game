# @space/server

Fastify + `@fastify/websocket`. Один маршрут `/ws`, вся логика матчей - в памяти процесса.

## Структура

```text
src/
  main.ts             запуск (слушает PORT, по умолчанию 3001)
  app.ts               buildApp(): сборка Fastify-приложения, разбор входящих WS-сообщений, маршрутизация в MatchManager
  match-manager.ts      Room, MatchManager: комнаты, коды приглашений, таймауты хода и отключения
  *.test.ts             тесты рядом с кодом
```

## Поток матча

1. Игрок подключается к `/ws` и шлёт `create-match`. Сервер создаёт `Room`, выдаёт `matchId`, 6-символьный код
   (без похожих друг на друга символов: без `0/O`, `1/I/L`) и секретный `token` для переподключения. Игрок занимает
   место 0. Партия (`GameState`) ещё не создана - ждём второго игрока.
2. Второй игрок шлёт `join-match` с кодом. Сервер создаёт партию (`createGame` с сидом из `crypto.randomInt`,
   **не** из детерминированного RNG `@space/engine` - тот только для игровой логики) и рассылает обоим первый `update`.
   Для игрока 0 это же сообщение - сигнал, что соперник подключился и игра началась.
3. Команды идут через `{ type: 'command', commandId, command }`. Сервер применяет `apply()` из `@space/engine`,
   отправителю - `ack`/`reject`, обоим игрокам - персональный `update` (`redact`/`redactEvents` под конкретного
   зрителя).
4. `sync` отдаёт полный снимок без событий - клиент использует его после переподключения или при рассинхронизации
   версий.

## Таймауты

- **Таймаут хода** (`turnTimeoutMs`, по умолчанию 90 000 мс): если игрок, чей ход (или кто должен ответить на
  открытый prompt), не действует вовремя, сервер сам выбирает и применяет действие - `SKIP`, если он доступен и
  есть открытый prompt, иначе `END_TURN`. Оба варианта всегда допустимы по правилам движка.
- **Таймаут отключения** (`disconnectTimeoutMs`, по умолчанию 60 000 мс): если сокет закрылся и игрок не
  переподключился по `reconnect` (с `matchId` + `token`) до истечения таймера, за него автоматически применяется
  команда `CONCEDE`, и соперник побеждает. Переподключение сбрасывает таймер.

Оба таймаута настраиваются через `buildApp(options)` / `new MatchManager(options)` - в тестах используются короткие
значения через `vi.useFakeTimers()`, чтобы не ждать реальное время.

## Известные ограничения (не входило в объём этапа 3)

- Комнаты не хранятся вне памяти процесса: перезапуск сервера обнуляет все текущие матчи.
- Завершённые и заброшенные комнаты (например, создатель так и не дождался второго игрока) не удаляются -
  нет сборки мусора.
- Один процесс, без горизонтального масштабирования: все матчи должны попадать на один и тот же инстанс.

## Команды

```bash
pnpm --filter @space/server dev         # node --watch src/main.ts
pnpm --filter @space/server test
pnpm --filter @space/server typecheck
```

`PORT` - порт HTTP/WS-сервера (по умолчанию 3001).
